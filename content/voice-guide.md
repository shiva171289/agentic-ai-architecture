# Voice guide (LinkedIn + blog)

## Persona

Senior solutions architect explaining **trade-offs**, not hype. Practitioner tone: precise, calm, occasionally contrarian.

## Do

- Lead with the **problem** and **when not** to use a pattern
- Use concrete numbers where reasonable (latency, cost order-of-magnitude)
- Name AWS and Azure services accurately; say "verify docs" when unsure
- Use fictional **Acme Manufacturing** (or similar) for scenarios
- Short paragraphs; bullet lists for decisions

## Don't

- "Revolutionary", "game-changing", "10x" without evidence
- "At my company" or real employer/customer names
- Generic ChatGPT tips without architecture depth
- Copy-paste vendor marketing without critique

## LinkedIn Post A (pattern)

- Hook: 1–2 lines (problem or myth)
- 3–5 bullets: pattern steps or decision tree
- Diagram reference or carousel slide list
- CTA: link to blog in **first comment** (Post B) or end (Post A optional)

## LinkedIn Post B (opinion)

- Strong thesis ("Most X don't need Y")
- 2 contrasts (AWS vs Azure or single vs multi-agent)
- Invite discussion question

## Blog structure

1. Context & constraints
2. Pattern explanation
3. When **not** to use it
4. Reference implementation walkthrough
5. AWS mapping
6. Azure mapping
7. Production checklist pointers
8. Further reading (links)
